# Native retention setup checkpoint

Diagnostic branch only. This workflow replaces the branch's CI definition and must never be merged. It is manually dispatched, uses a fresh GitHub-hosted macOS 15 runner, and performs only a single synthetic turn and an exact host snapshot/eviction receipt, release and restore. It has no 200-to-400 measurement or alternate retention configuration. No diagnostic artifacts or app logs are uploaded. Only fixed labels, counts, booleans and the synthetic fixture hash are printed; errors are intentionally reduced to the phase and a generic failure.

The production source is pinned to `8d30cf17f720e4014020aac8c345776a4372953e`. The controller rejects any production diff from that revision and any dirty checkout. It requires a hosted macOS runner, checks known ambient agent and credential paths are absent, creates fresh private state and profile directories, uses an allowlisted child environment and the separate fake executable, and removes its temporary files on normal completion. The copied fake rejects `command/exec` and `git-steer-run`, and its returned URLs point to loopback. Lead, phone, refresh and update checks are disabled; the account cloud and ACP registry point to loopback. Owned listener addresses are checked during the checkpoint.

**Observation boundary:** This is the parent-reviewed bounded fake setup, not a kernel network sandbox or proof that every possible startup path avoids outbound connections. No hosted execution has occurred; the re-pinned diagnostic still awaits review before dispatch. A fresh hosted account does not establish absence of all ambient state; the listed path checks are limited to known locations and fail closed if any exist. No claim about a retention plateau, whole-process memory, real vendor behavior, or account privacy follows from this checkpoint. The target includes the landed replay/cache-authority change. This setup checkpoint must pass before any later measurement is prepared.
