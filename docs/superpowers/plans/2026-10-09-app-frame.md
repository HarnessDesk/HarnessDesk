# One app frame: master plan

> **For agentic workers:** this is the index of the work, not a task list.
> Each phase below has its own plan file with the tasks; execute a phase's
> plan with superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build the frame in `docs/superpowers/specs/2026-10-09-app-frame-design.md`
— one shell, one 40px top bar, a right panel without a bar, pages in main
instead of a full-window overlay — as **one pull request**.

**Architecture:** The system changes before the screens (AGENTS.md rule 12).
A contract module holds the spec's numbers; tokens carry them to the
components; a rendered check measures the result; a frame wall shows every
destination for a visual review. Then the shell renders the top bar, the
panel frame and the status bar from slots the destinations register, and the
pages move into main one at a time.

**Tech Stack:** React 19, TypeScript, CSS modules + Tailwind v4 bridged to
`--hd-*` tokens, Base UI, Vitest + jsdom, Playwright (`playwright.ui-system.config.ts`),
`script/design-audit.mjs`, Electron (`packages/desktop`).

## How this lands: one PR, ordered commits

The owner chose one pull request. To keep it reviewable:

- **One commit per task**, in the order below. At every commit the design
  audit, the UI typecheck, the touched tests and the frame checks pass, so
  a review can go commit by commit and `git bisect` works.
- **A draft PR opens after phase A**, so CI runs on every push.
- **Main is merged in at the end of every phase** (and whenever it touches
  the same files), with `sync_with_base_branch`, never once at the end.
- **The Teams speed fix lands first** (session "Fix the Teams page speed and
  times", #1567/#1568). It edits `TeamsWindow.tsx`, which phase E rewrites;
  merge it in before phase E.
- **One writer moves the pages** (spec, "How it stays one app"): phase E's
  tasks run one at a time, never in parallel.

## The visual check (every task, every phase)

The owner's rule for this work: **a task is done only when it passes the
visual check**, so the build itself shows whether the app looks right. Four
layers, from automatic to human:

| Layer | What | Who runs it | Fails when |
| --- | --- | --- | --- |
| V1 Measured | `e2e/ui-system/frame-contract.spec.ts` compares computed sizes, edges and positions with `design/foundation/frame.ts` | the implementer, and CI on every push | a number differs from the spec |
| V2 Frames | `e2e/ui-system/frame-wall.spec.ts` captures every destination at 1440, 1100 and 720 in light and dark; `node script/frame-wall.mjs` puts them on one wall | the implementer, every task | a frame fails to render |
| V3 Look review | the reviewer opens every frame the task changed and answers the checklist below, frame by frame, next to the prototype | the task's reviewer | any checklist item is "no" |
| V4 Phase look | the built desktop app on the rig (isolated `HARNESSDESK_HOME`, fake agents), frames at wide and 720 in both themes, plus the wall, sent to the owner | the controller, at each phase end | the owner says no; their yes records the approved frames as the local baseline (`FRAME_WALL_COMPARE=1`) |

Pixel baselines are local only (`output/`, gitignored): CI's Linux renders
fonts differently from macOS, so a committed baseline would fail on font
smoothing rather than design. CI enforces V1; V3 and V4 judge the look.

### The look checklist (V3)

Answer each for every changed frame, in both themes. One "no" sends the task
back.

1. **Nothing broken.** No text clipped, overlapping or cut mid-word; names and
   paths may truncate with an ellipsis, sentences wrap. No horizontal scroll.
2. **The top bar is one calm row.** 40px; the title readable (at least
   180px); ⋯ at the window's right edge; no control on a second line; no
   filled button; icons at the same x as on the neighbouring destination.
3. **One left edge.** In every surface, the head, rows and footer start their
   text at one x; an icon hangs before the edge.
4. **The page has its measure.** A reading page is a centred 736 column with
   24px margins; a wide page 1320; nothing on a reading page runs to the
   window's edge; buttons are as wide as their words.
5. **Type from the scale.** Bar titles 14/500; no 20px title; group labels
   13/500 secondary; three ink levels, the faintest only on facts.
6. **Rhythm.** Label to card 8, section to section 32; no doubled gap, no
   cramped stack, no card inside a panel.
7. **Dark is as good as light.** Every text legible; no white box; hairlines
   visible and quiet.
8. **720 folds cleanly.** The panel and the left column float as the spec
   says; nothing overflows.
9. **It matches the approved drawing.** Same slots in the same order as the
   prototype's page for this destination; same tools in the panel.
10. **Real content holds.** Long names, second lines and CJK titles wrap or
    truncate as the blocks say, never widen a menu past 340.

The reviewer writes the verdict as a table (frame × item) in the task's
review note. "Looks fine" without the table is not a review.

### What each later phase must cover (so nothing in the spec is dropped)

Throughout: each new pattern (`TopBar`, the status bar, the info card, the
left column's row) gets its catalogue entry and example in the task that adds
it — `node script/ui-catalog.mjs` requires one — with real-length content
(second lines, long names, CJK titles), folded and unfolded. The spec's four
acceptance surfaces join V1 in the phase that moves them: a Team's Findings
(phase A), a Team's Chat (B), the conversation status card (B, as Details)
and the plan usage popup (C, as the wide menu).

**B — the fixed shell** (spec: The fixed shell, Bars, Where things go, Panels)
- `TopBar` pattern in `design/patterns` with the nine slots; `useTopBar`
  registration; the shell renders it once across main and the right panel.
- The conversation header (`Conversation.tsx` 733–808, draft included), the
  Team bar (`TeamRoomPane.tsx` 1080–1287), the Run header (`RunView.tsx`
  125–153), Board/Findings `ViewBar`, the Runs `PageHead` → slots. `ViewBar`
  deleted. `Bar size="lg"` removed.
- The Team bar's items moved per the spec's table (Seats in Details, Side by
  side in Chat's View menu, Hold messages in the composer's Send to menu, PR
  in Details and ⋯, trigger and commit in Details, Wrap and Fill in ⋯, the
  goal strip as the first card).
- The right panel: four tool icons + toggle before ⋯; no `DockPanelBar`,
  `DockPanelTabs`, `PanelActions` (split, move, zoom, collapse),
  `ToolPaneHeader` bars or titled cards in tool bodies. Inventory of every
  registered view (`panels/builtins.tsx`): run-details → Details;
  run-steps → the Run tab's Timeline in main; changes → Changes;
  activity, trajectory, tasks → Activity; agents (subagents) → Details' list;
  browser → Browser; file, preview, git (history), plugin → placed by the
  inventory, recorded in the phase plan before code moves.
- Nothing docks in the left column (`sidebar.panel` slot removed).
- The status bar (new): plan usage, other agents, background tasks, sync,
  updates; the terminal toggle.
- The fold: 1280 panel floats, 1000 left column floats (replaces
  `NARROW_WINDOW`/`rightPanelOverlays` thresholds); bottom panel max half the
  window. The dock limits in `state/workbench.ts` (`LIMITS`, today sidebar
  200–520 start 240, right 280–900 start 460, bottom 80–600 start 220) read
  `FRAME` instead: sidebar 200–360 (240), right 320–640 (400), bottom 120 to
  half the window (240); `workbench.test.ts` moves with them. Kept out of
  phase A because the fold logic and its tests are rewritten here anyway.
- `DockPanel.tsx`'s comment pointing at the nonexistent `--hd-topbar-h`
  goes with `DockPanelBar`.
- V1 grows: one 40px top row whose bottom shares one y across columns; ⋯ at
  one x on every destination; View at one x on every Team view; tools at one
  x on every piece of work.

**C — popups** (spec: Popups, "A menu decides once")
- `Menu` row is the only menu row; `PopoverOption` and `DropdownMenuItem`

**D — the left column** (spec: The left column)
- One 40px top row (window buttons, toggle, back/forward, notifications,

**E — main destinations** (spec: The shell and its destinations, Pages)
