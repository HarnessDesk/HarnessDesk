# One bar and the card rail implementation plan

> Execute the approved D1 design in `../specs/2026-10-14-panel-cards-and-team-bar.md`; the lead brief and issue #1654 comments settle the design.

**Goal:** Give sessions and Teams the same bar, separate subject cards from tool panes, and keep page controls in page bodies.

**Architecture:** Keep the existing per-subject tool cache and ownership. Add independent rail visibility and pane swapping to that model. Compose the shell from the existing design patterns; preserve mounted native resources while the regions move.

**Constraints:** Bar 40; inset 12; doors 28 on 32 pitch; sidebar floats below 1000; rail inset/gap 8, floating radius 12. Page tiers reading 736, wide 1320, canvas. Team board, Team pane redesign, Run graph and Flows remain in their own issues. No new dependencies or real identities.

- Test the bar's allowed controls first: title menu, state dot, rail, Terminal/Changes/Browser/Files, More. Remove visible tabs, parents, view choosers and worded verbs; preserve actions through body controls or More.
- Test independent rail/pane state and retained resources, then extend `ToolIntent`, the store and `FixedShell`/`Workbench`. Keep `WorkDetailsOutlet` as the rail content contract.
- Test and relocate Background tasks and folded Trajectory into `ConversationDetails`; move History into Changes and make Events a Trajectory filter.
- Test page body controls and Page tiers; use `PageOptions` for verbs and choosers. Extend `container-insets.spec.ts` to measure actual destination widths.
- Update browser contracts to the approved geometry and controls, exercising all bars, pane closing/swapping and narrow rail placement.
- Run focused Vitest suites, UI typecheck, design gates and the affected browser specs; fix failures. Run `pnpm check:push` unpiped before each push.
- Inspect light/dark before/after preview frames for session, Library, Team and narrow window. Commit source through `commit_work`; publish source and a separate frames branch, then open a draft PR with image tables and validation evidence. Never merge.
