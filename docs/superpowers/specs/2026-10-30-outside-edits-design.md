# Outside-edit labels for issue #1603

Keep all observed turn edits and their total, and visibly distinguish files whose reported paths fall outside the renderer's known open workspace and conversation roots. For example, “Edited 7 files” gains a neutral “1 outside” chip; each affected file gains “Outside”. The Changes pane retains its turn total and labels affected files in navigation and headings, including when navigation is hidden. Git/commit counts continue to describe the current repository worktree and need not equal the runtime's turn snapshot.

Use only existing renderer metadata and design-system chips/tooltip controls. Known roots are current workspaces[].path, selected workspace.path, and valid absolute cwd values of the displayed and other known sessions. Do not add permission-only settings.workspaceRoots merely because the runtime may access them: allowed access does not establish an opened workspace. Describe the scope honestly as known roots, not a complete host registry. Recompute on root/session changes; no stale classification cache.

Resolve a relative reported path against the displayed session's absolute cwd, normalize dot segments and path-component boundaries, and reuse existing Windows separator/case conventions. A prefix sibling is outside; a path under a second known workspace is inside. Empty/malformed/ambiguous paths or relative paths without a usable cwd are unknown and receive a modest “Location unknown” indicator. Tooltip: “Reported path is outside the known open workspace and conversation roots.” This is a lexical description of reported paths; it does not resolve symlinks or decide access. Existing host access/undo confinement stays authoritative and unchanged. No new wire method, filesystem request or generic visual primitive.

Extend existing path, TurnFiles, Changes and diff-reader coverage for inside/outside/unknown, second workspace, relative paths, Windows forms, root changes, single/mixed/expanded files, filtering and hidden navigation. Verify unchanged totals and undo requests. After implementation, validate both surfaces in the isolated fake-agent desktop rig at narrow and regular widths with full unchanged privacy audits. Publish only independently inspected safe frames.

Alternative: exclude outside edits and reduce counts. This is smaller visually but hides observed edits, so labeling is recommended. Deferring the change keeps the current ambiguous count.
