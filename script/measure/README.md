# Library measurement harness

This is a manual, macOS-only measurement tool and never runs in CI. Discovery measures installed-build help and version output, plus sign-in-free catalogue observations: Codex `app-server` `skills/list` and signed-out ACP `initialize`/`session/new`. ACP command updates are recorded only as commands; they never count as skills. A failed ACP `session/new` records the asked observation “no session while signed out,” while skill catalogue availability stays `unknown`. Discovery sends no model prompts and uses no sign-in.

Run the exact entry point after building the generated install metadata:

```sh
pnpm build:node && node script/measure/library.mjs --all
```

Measure just one agent with `--agent <id>`. Without `--ask` this performs exactly that agent's discovery. To send fixed model questions in one session, explicitly select one agent:

```sh
node script/measure/library.mjs --agent gemini --ask --env GEMINI_API_KEY
node script/measure/library.mjs --agent claude-code --ask
```

`--all --ask` is refused. An absent agent records `binary not installed` and exits 0. Every installed agent's ask run requires a successful preflight of its selected profile in this process; a forged flag or changed profile cannot authorize a launch.

`--env <NAME>` admits one caller environment variable only when the selected registry entry declares it as a sign-in secret (`GEMINI_API_KEY` for Gemini). An undeclared name is refused before discovery. A missing value records `could-not-ask: key not provided`. Discovery never receives the key. The key is passed only in the probe child's environment; the harness never puts it in arguments, prompts, files or logs, nor echoes it. Raw protocol responses stay inside the isolated driver, whose stderr is discarded; only exact fixture matches leave it for capture or persistence. Results say `auth: environment key`, without the name or value.

The harness makes a fresh fixture per agent under `/tmp/hd-measure-*`: isolated synthetic home and repository, user/project/duplicate/invalid/oversized skills, rule sentinels, MCP configs, and a local fixture MCP peer. Child processes receive only the sanitized environment, fixture cwd and homes, fixture `TMPDIR`, and the selected CLI arguments. The fixture and captures are removed after its result is written.

Before launching a probe, `sandbox-exec` preflight checks the exact profile. The strict profile starts with `(allow default)`, denies file reads and writes under `/Users` and `/Volumes`, then denies all writes before allowing writes only in the fixture roots, `/dev/null`, and `/dev/tty*`. Reads are allowed for fixture roots and the resolved Node and agent install directories; final denials cover each credential root and known-agent home so those cannot inherit an install-directory allowance. Strict mode also denies the real home Keychains directory and the `securityd` and `SecurityServer` lookups. Canary checks prove an unrelated read under a synthetic home, a credential read inside an allowed install directory, and an outside-fixture write fail; fixture reads and writes, an allowed install read, and spawning `/usr/bin/true` succeed. A direct file read of a disposable fixture keychain succeeds only in the keychain-read-only control.

Discovery runs under strict isolation for every agent. Only `--agent <id> --ask` for Claude Code (`claude-code`), Cursor (`cursor`) and Grok Build (`grok-build`) selects `keychain-read-only`; every other path stays strict. The exception allows reads under the real home’s keychain directory and **direct file writes to the keychain directory are denied**. It allows Mach lookups to `com.apple.securityd` and `com.apple.SecurityServer`: **Keychain Services calls through these allowed security services are not constrained**, including adding or updating the agent's own item. **Network access is unrestricted** in both profiles, so even a vendor CLI's discovery may reach the network. This change adds no sandbox rule.

Ask results record the actual `isolation` and `auth`. `owner subscription sign-in` is recorded only for an exception ask run that sent a prompt without an environment key; refusals before prompting and strict runs without a key say `no sign-in used`. Discovery keeps its existing result format.

Install discovery keeps absent candidates, unreadable versions, and unsafe-to-isolate install roots separate. It resolves symlinks before selecting a narrowly scoped install directory; a package or `versions/<version>` directory inside the current agent home can be allowed, but the whole config home cannot. An install directory that is a whole home or a whole volume is refused. An install directory under another account’s home or on an external volume is refused. Node-based agents also get the resolved Node install prefix, held to the same rule; the harness refuses to start when it is not a safe read root. Unsafe or inseparable roots remain `could-not-ask` with a path class in the reason; no real path is persisted.

Claude Code and Cursor resolve the bridges shipped with HarnessDesk, just as `AgentRegistry` expands their app templates: Node runs `packages/claude-acp/dist/src/main.js` or `packages/cursor-acp/dist/src/main.js`. The selected CLI path goes only into the bridge's executable environment variable, and Claude's nested-session marker is cleared. Resolution reads the built files and installs nothing; a bridge absent from this build records `could-not-ask: bridge not installed`. Restore the repository dependencies with `pnpm install --frozen-lockfile`, then run `pnpm build:node` to build these packages. No global bridge install or registry download is required.

Node's normal import loader reads ancestor metadata while resolving symlinks; the strict home denial refuses that access even when the package itself is a safe read root. The harness therefore stages copies of the resolved bridge and its already-installed runtime dependencies (including peers) inside the disposable fixture and runs the copied entry. Each canonical source package must pass `installRootIsSafe`. At most 500 distinct packages are copied, dependency links point to the staged copies, and the originals are only read. Missing required dependencies record `bridge not installed`; an unsafe source root records `cannot isolate: bridge install directory unsafe`. Staging adds no sandbox rule, no bridge read allowance outside the fixture, no HOME redirection and no install step.

Ask RPC refusals record a fixed `reason`: `sign-in not reachable under the approved profile`, `network refused`, `quota`, or `unknown`. `facts.requestFailure` contains only the stage (`initialize`, `session-new` or `prompt`) and a fixed JSON-RPC error class. ACP's authentication-required code is distinguished from a generic server error; vendor messages and error data are reduced inside the isolated driver and never leave it. Missing bridges, process launch failures and unanswered requests retain separate reasons. A pre-prompt refusal still records `auth: no sign-in used`.

Measured 2026-10-03 against Grok Build 1.0.30: under the unchanged `keychain-read-only` profile, `initialize` answered and `session/new` refused with ACP error code -32000 (`authentication-required`). The reduced result was `could-not-ask: sign-in not reachable under the approved profile`, stage `session-new`, with zero prompts. The diagnostic used an isolated synthetic home and sent no sign-in request. Its raw error text was discarded; changing sign-in access remains the owner's decision.

Discovery interfaces and scope:

- Codex: `codex app-server`; query `skills/list`, config and MCP status without sending a model prompt.
- Gemini CLI, OpenClaw, OpenCode, Cline, Hermes, CodeBuddy Code, Kimi, Pi ACP, GitHub Copilot CLI, Antigravity, DeepSeek, and Devin: the configured ACP bridge or agent command; send only `initialize` and `session/new`, never a prompt. Claude Code, Cursor, and Grok Build receive version/help discovery only; no ACP session or model prompt is sent.
- All builds: capture `--help` and the declared version arguments in the fixture, compare the parsed version with install discovery, and persist only the normalized version. Absent, unreadable, unsafe, and version-changed candidates remain distinct.

Raw answers are reduced to fixture-derived sentinel tokens. Structured model facts accept only fixed enums, booleans, integer counts from 0 to 500, fixture tokens, and concrete relative skill-root paths. Discovery retains its numeric protocol error codes. Vendor output, account identifiers, emails, tokens, secrets and absolute machine paths are never persisted or printed. A failed privacy validation becomes `could-not-ask`.

Ask runs use ACP `session/prompt` or Codex `turn/start`, with one session/thread per fixture. The harness counts requests at the protocol send: at most three prompts, including failures, and a fourth is refused. No user or fixture text enters a prompt, and no full sentinel token appears in one. The first fixed question requests only JSON containing rules, skill names/descriptions and MCP names. Only known rule tokens, exact skill name/description pairs and the fixture MCP name survive. Root-unique descriptions identify the relative root actually reported; duplicate descriptions show precedence, while missing-description and oversized names show listing, never an inferred rejection reason. Rule order is the order reported by the agent.

The harness then rewrites one `measure-sentinel` description and asks for its description in the same session. Only the new description establishes `openSessionSeesChange: yes`; the exact old description establishes `no`; anything else is `unknown`. Catalogue refresh support and skill toggles remain unmeasured. The third prompt is reserved exclusively for one repeat of a malformed first answer, after the refresh question. The new sentinel is admitted to that repeat only after the harness wrote it. Malformed refresh JSON records `could-not-ask` without retry. Every prompt has a 90-second deadline; a timeout records `could-not-ask: prompt timed out` without retry. Earlier sanitized facts may survive a later refusal, but its raw answer is empty.

The generic ACP driver sends integer `protocolVersion: 1`, empty client capabilities and client information, then `session/new` with an absolute fixture cwd and no MCP servers. ACP has no `initialized` notification. Requests and captured responses stay newline-delimited JSON. An initialize error stops the handshake and records `no-session`; a session error also records `no-session`. Only a request timeout records no answer; a failed launch has its own reason. A session timeout retains an earlier initialize answer.

`facts.signedOutCatalogue` records `initializeAnswered`, `sessionNewAnswered`, `signInMethodCount` (only the length of `authMethods`), and numeric `initializeErrorCode` / `sessionNewErrorCode` when present. It never stores sign-in method names, descriptions, session identifiers or error messages. Catalogue status stays `unknown`, including when a session succeeds.

Run the regression suite explicitly (it is a manual harness, outside the gate-test glob):

```sh
node --test script/measure/library.test.mjs
```

The subprocess tests use the scripted ACP fixture with strict v1 validation and request capture added to a disposable copy. They cover success, sign-in refusal, initialize refusal, timeout preservation and launch failure without running a vendor agent. The mutation proof restored a byte-exact backup of the original probe: the session-success test failed with `could-not-ask` instead of `asked` (exit 1). Restoring the fixed backup was checked byte-for-byte and the focused suite passed.

Ask tests use disposable copies of the ACP and Codex scripted peers. They exercise fixed questions, a single session, JSON retry/refusal, refresh, timeout, fabricated sentinels and a synthetic environment value echoed on both protocol and stderr. The result/capture checks retain neither value. The profile-selection test enumerates every registered agent and the isolation selection sites, and the sandbox profile source is pinned unchanged. Mutation proofs remove the prompt cap, environment-name guard and profile guards one at a time; each must fail its focused test, with the original restored byte-for-byte before the suite is run again. No real agent receives a model prompt in these proofs.

Bridge regressions resolve and stage disposable copies of the scripted ACP peer, then launch them under `keychain-read-only`. They check both executable environment variables, the Claude marker, missing/unsafe bridge refusals and zero prompts. An import-only check loads both real bundled bridge modules and their staged dependency trees under the same profile without starting a session or running a vendor CLI. Request-failure regressions exercise initialize, session and prompt errors, validate the persisted stage/error class, and prove that synthetic raw error details survive in neither captures nor result files. `probeAcpHandshake` is a diagnostic export that shares ask startup and its error reducer, sends no MCP servers, and stops before any model prompt; it must be used through `run` with a preflighted fixture.

`docs/verification/library-measurements/README.md` maps each result JSON cell to its fact: `facts.rulesFiles` → rules read/load order; `facts.catalogue` plus `facts.reportsCatalogue` → fixture reach/catalogue reporting; `facts.precedence` → duplicate-name precedence; `facts.rejections` plus `facts.reportsRejections` → acceptance/reason and rejection reporting; `facts.skillRoots` → concrete tier C root paths; `facts.refresh.catalogueRefresh`, `facts.refresh.skillToggle`, and `facts.refresh.openSessionSeesChange` → refresh behavior; `facts.mcp` → config recognition and connection status; `facts.signedOutCatalogue` → available/empty/unknown while signed out. Each cell links its exact `<agent>-<version>.json` result or gives its `could-not-ask` reason.
